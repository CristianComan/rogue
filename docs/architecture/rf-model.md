# ROGUE RF Model and Environment Compiler

## 1. Purpose

The RF Environment Compiler is the boundary between **scenario intent** and **hardware execution**. It resolves missions, RF-link behaviour, receiver geometry, SigMF assets, spectrum constraints, safety policy and available SDR capabilities into a deterministic **Replay Plan**.

```text
Scenario
  "What should happen?"
        |
        | compile
        v
Replay Plan / Run Manifest
  "Exactly what must each RF resource do?"
        |
        | execute
        v
SDR Agents + RF distribution
```

## 2. RF domain concepts

- `DroneRfLink`: logical C2/telemetry/video/data link.
- `RfBand`: allowed band/range/channel plan.
- `RfEmission`: logical waveform instance.
- `FrequencyBehaviour`: rules for instantaneous frequency.
- `FrequencyEvent`: realized channel/band change with reason.
- `RfWindow`: contiguous wideband RF canvas centered on a physical TX path.
- `CompositeChannel`: DSP composition assigned to an RF window.
- `PhysicalTxChannel`: actual SDR TX resource.
- `HardwareCapability`: runtime-discovered constraints.
- `Allocation`: mapping generated by the compiler/scheduler.

## 3. Frequency behaviour

ROGUE supports realistic frequency-agile behaviour, including multiple drones at slightly different or overlapping frequencies in the same band.

Switching modes:
1. scripted at scenario times;
2. mission/position-triggered (waypoint/geofence/phase);
3. probabilistic/adaptive using allowed channels and dwell distributions, deterministic when seed is fixed;
4. approved external/state-triggered.

Two explicit transition types are mandatory:

### CHANNEL_SWITCH
Frequency changes within the currently allocated RF window. Prefer changing the digital NCO/offset without retuning the physical LO.

### BAND_SWITCH
Movement to another RF band/window. This may require scheduler reevaluation, another physical channel, LO retune, or migration to a different SDR.

Every realized change records selected frequency, reason and deterministic seed/context.

## 4. Composite wideband replay

One physical TX channel is a wideband RF window, not necessarily one drone. Multiple recordings may share a channel when translated spectra fit within usable instantaneous bandwidth and guard margins.

For logical emission `i`:

```text
s_i(t) = A_i(t) · IQ_i(t - τ_i) · exp(j(2π Δf_i(t)t + φ_i(t)))
```

and composite output:

```text
x(t) = Σ_i s_i(t)
```

`Δf_i(t)` includes offset from RF-window center plus scenario Doppler. Implement frequency translation with numerically stable NCO/phase accumulation rather than large absolute-time phase recomputation.

Streaming pipeline:

```text
bounded SigMF reader
  -> optional resampling
  -> complex frequency translation / NCO
  -> gain / calibrated power
  -> Doppler
  -> delay / phase
  -> complex summation
  -> peak/RMS/headroom assessment + backoff
  -> SDR adapter
```

Full recordings must not be loaded into RAM.

## 5. Spectrum planning and deconfliction

The planner/compiler shall:
- preserve intentional spectral overlap;
- enforce usable bandwidth and guard margins;
- detect impossible placement;
- assess sample-rate compatibility;
- calculate aggregate peak/RMS/headroom and clipping risk;
- apply configurable normalization/backoff;
- assess aggregate power and intermodulation risk;
- distinguish conflicts from deliberate overlap;
- re-evaluate allocations at scheduled band/window changes.

## 6. Receiver geometry and propagation

Each receiver has geodetic position and type.

### Single-channel monitoring
Generate the applicable received emission mixture with configured propagation effects.

### TDOA
For transmitter position `p_tx(t)` and receiver `r_k`, geometric delay is conceptually:

```text
τ_k(t) = |p_tx(t) - p_rk| / c
Δτ_kj(t) = τ_k(t) - τ_j(t)
```

The compiler creates controlled relative delays for synchronized receiver channels.

### AOA/DOA
For antenna/receiver element geometry, compute channel-dependent phase and, where applicable, delay relationships. Phase relationships must remain coherent to the declared synchronization/calibration capability.

The same emission may therefore generate different synchronized streams for different receiver sites/elements.

## 7. Replay Plan

The Replay Plan is immutable for a run and contains at minimum:
- scenario/version and compiler version;
- recording asset hashes;
- realized frequency events;
- RF windows and center/bandwidth;
- constituent logical emissions;
- physical SDR/device serial/TX channel allocation;
- sample rates and resampling decisions;
- digital offsets/NCO schedule;
- gain/power/backoff;
- Doppler schedule;
- delay and phase schedule;
- timing/synchronization method;
- external converter/calibration chain if used;
- safety policy outcome;
- validation expectations.

## 8. Resource scheduler

Allocate logical emissions based on:
- RF frequency range;
- instantaneous/usable bandwidth;
- sample rate;
- physical channel availability;
- timing/clock domain;
- external frequency converters;
- safety policy;
- receiver synchronization requirements.

Prefer stable assignments for intra-band changes. Permit migration for band changes. Actual allocation is evidence and belongs in the immutable run manifest.

## 9. Independent RF validation

RF Validation & Monitoring is independent of the replay command path. Compare measured/captured output against the Replay Plan for occupied frequency, bandwidth, timing, relative power, overlap and synchronization quality. Attach validation results and evidence to the ScenarioRun.
